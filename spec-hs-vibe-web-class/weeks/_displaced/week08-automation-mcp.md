## 1. 커스텀 커맨드란 무엇인가

### 1.1. 한 줄 정의

**커스텀 커맨드** = 자주 쓰는 프롬프트를 **저장해 두고 짧게 불러 쓰는 것**.  
예: 매번 긴 문장을 치는 대신 `/commit` 한 번.

### 1.2. 왜 필요한가

| 커맨드 없이 | 커맨드로 |
|--------------|-----------|
| 매번 같은 긴 프롬프트를 타이핑 | 짧은 명령 한 번 |
| 팀원마다 표현이 달라짐 | 같은 결과를 **일관되게** 재현 |
| 실수로 조건을 빠뜨림 | 저장된 프롬프트라 **빠짐없음** |

### 1.3. 커맨드 파일 구조 (개념)

도구에 따라 `.claude/commands/`(또는 동등 폴더)에 **파일 하나 = 커맨드 하나**로 저장된다.  
파일 안에는 「이 커맨드를 실행하면 AI가 할 일」이 프롬프트 형태로 적혀 있다.

## 2. 커맨드 만들기 함께

### 2.1. 예시 ① `/commit` — 커밋 메시지 자동 생성 + 커밋

```markdown
변경된 파일을 확인하고, "무엇을 + 왜" 형식의 커밋 메시지를 제안해줘.
내가 승인하면 add → commit까지 실행해줘.
```

### 2.2. 예시 ② `/readme-update` — README 최신화

```markdown
현재 프로젝트 구조를 다시 읽고, README.md의 "폴더 구조" 섹션만
최신 상태로 업데이트해줘. 다른 섹션은 건드리지 마.
```

### 2.3. 직접 만들기 (학생 실습)

```
아래 프롬프트를 커스텀 커맨드로 만들어줘. 이름은 /(원하는 이름).

(자주 쓸 것 같은 프롬프트 내용)
```

**팁:** 5주차 「커밋 메시지 연습」, 7주차 「README 3단계」에서 이미 만든 습관을 그대로 커맨드로 옮기면 쉽다.

## 3. 서브에이전트 — 역할 나누기 입문

### 3.1. 한 줄 정의

**서브에이전트** = 하나의 AI가 다 하는 대신, **역할을 나눠 맡기는 것**.  
예: 「작성하는 AI」와 「검토하는 AI」를 분리.

### 3.2. 왜 유용한가

같은 대화 안에서 스스로 검토하면 **자기가 쓴 것을 다시 좋게만** 보기 쉽다.  
독립된 시각(서브에이전트)으로 검토하면 **놓친 부분**을 더 잘 찾는다.

### 3.3. 코드리뷰 서브에이전트 데모 (교사 시연 → 학생 관찰)

```
방금 만든 커맨드 파일을 코드리뷰 관점에서 검토해줘.
1) 잘한 점 1개
2) 개선하면 좋을 점 1개
간단하게만.
```

**포인트:** 「검토 전담 역할」을 따로 부르는 감각. 오늘은 **1회 체험**이면 충분.

## 5. 🟡 MCP란 무엇인가

### 5.1. 한 줄 정의

**MCP(Model Context Protocol)** = AI에게 **외부 도구를 꽂아주는 플러그인** 방식.  
비유: AI 도구에 꽂는 **USB 확장 포트**.

### 5.2. 왜 유용한가 (예시)

| MCP 서버 예 | 하는 일 |
|--------------|---------|
| Context7 | 최신 공식 문서를 찾아 정확한 사용법 제공 |
| Playwright MCP | 브라우저를 열어 UI를 직접 확인·테스트 |

### 5.3. MCP 1개 설치 함께 (교사 데모 + 학생 실습)

학급 표준 MCP 1개(예: Context7)를 함께 설치하고, 실제 질문 1개를 던져 응답을 확인한다.

```
Context7으로 (사용 중인 라이브러리)의 최신 사용법을 찾아서 알려줘.
```

### 5.4. 주의: MCP 과다 설치

MCP를 너무 많이 연결하면 **AI가 매번 읽어야 할 도구 설명이 늘어나** 오히려 느려지고 헷갈릴 수 있다.  
**오늘은 1개만.** 필요할 때 하나씩 추가하는 습관.

## 6. 🔴 도전: 리뷰 에이전트 · Hooks·Skills 맛보기

### 6.1. 코드리뷰 서브에이전트 1회 실행 (도전)

3장의 데모를 **직접** 해본다. 자신의 커맨드 파일이나 Kit 코드 일부를 검토받는다.

### 6.2. Hooks(개념만)

**Hooks** = 특정 상황(예: 커밋 직전)에 **자동으로 실행되는 규칙**.  
오늘은 실습하지 않고, 「커맨드는 내가 부르는 것, Hooks는 자동으로 걸리는 것」정도만 구분한다.

### 6.3. Skills(개념만)

**Skills** = 특정 작업을 위한 **패키지된 지식/절차**(이 강의 자료도 넓게 보면 Skills와 비슷한 개념).  
5줄 이내로 무엇인지 조사해보는 것도 🔴 선택 과제.

## 교사 메모

### 진행 팁
- 훅 + Slack 연동·마켓플레이스 플러그인 배포·Agent Teams는 **이 과정에서 다루지 않는다.**  
- MCP는 **1개만** 확실히 연결하는 것을 목표로 — 여러 개 설치하면 컨텍스트 낭비·오류 원인 증가.  
- 서브에이전트는 「완전히 다른 기능」이 아니라 **「관점을 분리해서 물어보는 습관」**으로 설명하면 이해가 빠르다.  
- 시간이 부족하면 🟢(커맨드)만 확실히, MCP·서브에이전트는 개념 설명 + 교사 데모로 대체 가능.

### 설명용 한 장 요약 (칠판)

```
커맨드     → 자주 쓰는 프롬프트를 저장해 짧게 부르기
서브에이전트 → 역할을 나눠서 맡기기 (작성 vs 검토)
MCP        → 외부 도구를 AI에 꽂는 플러그인
Hooks      → 자동으로 걸리는 규칙 (개념만)
Skills     → 패키지된 지식/절차 (개념만)
오늘 결과   → Kit + 커맨드 1개 + (선택) MCP 1개
다음       → 미니앱 PRD·ROADMAP (Week9)
```

### FAQ

**Q. 커맨드와 그냥 프롬프트를 복사-붙여넣기 하는 것의 차이는?**  
A. 커맨드는 **파일로 저장되어 프로젝트와 함께 관리**된다 — 팀/미래의 나와 공유 가능.

**Q. MCP를 여러 개 설치했는데 이상해요.**  
A. 오늘 배운 「과다 설치 주의」 사례. 필요 없는 것은 끄고 1개만 남기기.

**Q. 서브에이전트를 꼭 써야 하나요?**  
A. 오늘은 **체험**이 목표. 실전에서는 필요할 때만 쓰면 충분.

**Q. Hooks/Skills를 실습하고 싶어요.**  
A. 시간이 남는 🔴 학생만. 본 과정에서는 개념 이해까지만 다룬다.
