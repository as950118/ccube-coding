## 오늘 완성할 프로그램

### 산출물 이름
**「나만의 Web Starter Kit (v0)」**

4~6주차의 프로필 프로젝트와는 **별개의 새 저장소**다.  
이번엔 콘텐츠(프로필)가 아니라, **다음 프로젝트마다 재사용할 뼈대**를 만든다.  
(9~10주차 미니앱을 만들 때 이 Kit에서 시작하게 된다.)

### 완성 모습 (최소 · 🟢)

| # | 항목 | 최소 내용 |
|---|------|-----------|
| 1 | **로컬 실행** | Vite(또는 Live Server)로 개발 서버가 브라우저에서 보임 |
| 2 | **Starter Kit 구조** | README / CLAUDE.md / styles / scripts / .gitignore |
| 3 | **GitHub repo** | Kit이 저장소로 올라가 있음 (node_modules는 제외) |
| 4 | **CLAUDE.md** | 「이 Kit로 만들 앱 종류」가 한 문장 이상 적혀 있음 |

### 폴더 구조 (수업 종료 시 예시 · Vite vanilla 기준)

```
my-web-starter/
├── README.md
├── CLAUDE.md
├── .gitignore
├── index.html
├── src/
│   └── main.js
├── styles/
│   └── main.css
└── notes/
    └── prompt-log.md      ← (선택) 오늘 프롬프트 연습 기록
```

> 순수 HTML/CSS/JS + Live Server로 진행해도 무방하다. **학급 표준 하나로 통일** 권장.

### 성공 기준 (🟢)
1. Starter Kit repo가 GitHub에 있다  
2. `npm run dev`(Vite) 또는 Live Server로 **로컬 실행**된다  
3. CLAUDE.md에 「이 Kit로 만들 앱 종류」가 명시되어 있다  
4. `.gitignore`로 `node_modules`가 **커밋되지 않았다**

## 1. Phase2 오리엔 — 모던 스택 지도

### 1.1. Phase1 vs Phase2

| Phase1 (3~6주차) | Phase2 (7주차~) |
|--------------------|-------------------|
| HTML/CSS 파일을 직접 편집 | **빌드 도구**(Vite 등)로 개발 서버 실행 |
| 새로고침으로 확인 | 저장하면 **자동 반영**(Hot Reload) |
| 파일 몇 개로 충분 | **프로젝트 구조**(폴더 규칙)가 생김 |
| 프로젝트마다 매번 새로 시작 | **Kit(템플릿)**에서 시작 |

### 1.2. 왜 빌드 도구가 필요한가 (개념)

- 파일이 많아질수록 **자동으로 묶고 최적화**해주는 도구가 필요하다  
- 컴포넌트(버튼·카드 등)를 **재사용**하기 쉬워진다  
- 실제 개발 현장에서도 널리 쓰는 흐름이다

### 1.3. 오늘 스택 선택 (학급 표준 확정)

| 옵션 | 언제 |
|------|------|
| **Vite + vanilla JS** (기본 권장) | React 경험이 없거나 처음인 학급 |
| 간단 React | 이미 JS 기초가 탄탄하고 시간 여유가 있는 경우 |

> **수업 표준:** 특별한 사유가 없으면 **Vite + vanilla**로 통일한다.  
> Next.js·Shadcn 같은 「풀코스」는 이 과정에서 **필수 아님**.

### 1.4. 오늘 하지 않는 것 (Non-goals 안내)

- 상태관리 라이브러리(Redux 등)  
- 백엔드·데이터베이스 연결  
- 복잡한 라우팅(여러 페이지 이동 구조)

## 2. 더 정교한 프롬프트 — CoT · 역할 프롬프트

### 2.1. 지금까지 써 온 프롬프트 패턴 복습

```
목표: ...
제약: ...
Non-goals(하지 않을 것): ...
```

오늘은 여기에 두 가지를 더한다.

### 2.2. CoT(Chain of Thought) — 「생각 과정을 먼저 보여줘」

```
이 폴더 구조를 어떻게 짤지, 먼저 이유와 함께 3단계로 설명해줘.
그다음에 내가 승인하면 실제로 만들어줘.
```

**포인트:** 결과만 받지 않고, **왜 이렇게 하는지** 과정을 먼저 확인하는 습관.

### 2.3. 역할 프롬프트 — 과장 없이 「조건을 분명히」

| 과장된 역할 프롬프트 (지양) | 조건을 분명히 한 프롬프트 (권장) |
|------------------------------|-----------------------------------|
| 「너는 세계 최고의 시니어 개발자야」 | 「중학생도 이해할 수 있게, 최소 구성으로」 |
| 「완벽하게 만들어줘」 | 「Vite vanilla 템플릿 기준으로, 불필요한 라이브러리 추가 금지」 |

> 역할극보다 **구체적 제약**이 실제 결과 품질에 더 크게 기여한다.

### 2.4. 좋은 프롬프트 3요소 (오늘의 기준)

1. **목표** — 무엇을 만들 것인가  
2. **제약** — 무엇을 쓰고, 무엇을 쓰지 않을 것인가  
3. **검증 기준** — 무엇이 되면 「완료」인가

## 3. Starter Kit이란 & 생성 데모

### 3.1. 왜 Starter Kit인가

- 새 프로젝트마다 **README/CLAUDE.md/폴더 구조**를 매번 새로 만들지 않는다  
- CLAUDE.md에 **기본 규칙**이 이미 있어 AI가 빠르게 온보딩된다  
- 「예쁜 UI」보다 **폴더 구조 · README · 스크립트**가 오늘의 핵심이다

### 3.2. Starter Kit 최소 구성 (수업 표준)

```
README.md
CLAUDE.md
index.html (또는 src/)
styles/
scripts/ (또는 src/)
.gitignore
```

### 3.3. 공식 템플릿으로 생성 데모 (교사 시연)

```
npm create vite@latest my-web-starter -- --template vanilla
cd my-web-starter
npm install
npm run dev
```

> `npm`/`Node.js`가 준비되어 있어야 한다 (3주차 환경 세팅에서 확인한 항목).  
> Node.js가 없다면 순수 HTML/CSS/JS + Live Server 방식으로 대체 진행.

## 4. Kit 생성 · 로컬 실행 (🟢 핵심)

### 4.1. 함께 따라하기

1. 원하는 위치에 새 폴더에서 `npm create vite@latest` 실행  
2. 템플릿 선택: **Vanilla** (JS)  
3. `cd my-web-starter` → `npm install` → `npm run dev`  
4. 터미널에 뜬 주소(예: `http://localhost:5173`)를 브라우저로 열기

### 4.2. Live Server 대안 (Node 없이)

Vite 대신 단순 `index.html` + VSCode/Cursor의 **Live Server** 확장으로도 오늘 목표(로컬 실행 확인) 달성 가능. Starter Kit 폴더 구조만 동일하게 맞춘다.

### 4.3. CLAUDE.md 작성 — 「이 Kit로 만들 앱 종류」

```
AI에게:

이 프로젝트는 앞으로 여러 미니앱을 시작할 때 쓸 Starter Kit이야.
CLAUDE.md를 만들어줘. 포함할 것:
1) 이 Kit의 목적 (재사용 가능한 시작점)
2) 기술 스택 (Vite + vanilla JS, 프레임워크 추가 전 상의)
3) 폴더 구조 규칙
4) 새 프로젝트를 시작할 때 지켜야 할 것
```

### 4.4. `.gitignore` 정식 도입 (처음 등장)

이번 주부터 `node_modules/` 같은 **용량 크고 재생성 가능한 폴더**는 커밋하지 않는다.

```
node_modules/
dist/
.env
.DS_Store
```

**규칙:** `npm install`로 다시 만들 수 있는 것은 저장소에 올리지 않는다.

## 5. GitHub에 Kit 올리기

### 5.1. 흐름 복습 (5주차 연계)

```
git init
git add .
git commit -m "Starter Kit 초기 구조"
git branch -M main
git remote add origin <repo URL>
git push -u origin main
```

**주의:** `.gitignore`를 **`git add .` 전에** 먼저 만들어 둔다. (안 그러면 `node_modules`가 이미 추적될 수 있음 — 걸리면 교사·조교 호출)

### 5.2. 검증 체크리스트

- [ ] GitHub repo에 `node_modules/`가 **보이지 않는다**  
- [ ] README·CLAUDE.md·styles·scripts(.gitignore 포함)가 모두 보인다  
- [ ] repo를 새로 클론해도 `npm install` 후 바로 실행될 것 같은 구조다 (개념 확인 · 실제 클론은 선택)

## 6. 🟡 디자인 토큰 & README 3단계

### 6.1. 디자인 토큰이란 (개념)

색상·폰트 같은 값을 **CSS 변수**로 한곳에 모아두는 방식. 나중에 색 하나만 바꿔도 전체가 바뀐다.

```css
:root {
  --color-bg: #ffffff;
  --color-ink: #1a1a1a;
  --color-accent: #2f6f5b;
  --font-body: "Noto Sans KR", sans-serif;
}
```

### 6.2. README에 「새 프로젝트 시작 방법」 3단계

```markdown
## 새 프로젝트 시작 방법

1. 이 저장소를 복제(clone)하거나 폴더를 복사한다
2. `npm install`
3. `npm run dev`로 로컬 서버를 연다
```

## 교사 메모

### 진행 팁
- React가 부담이면 **Vite + vanilla**로 학급 전체 통일 — 개인별 스택 분산은 오늘 목표(재사용 가능한 뼈대)를 흐린다.  
- 「Next + Shadcn 풀코스」는 이 과정에서 **필수 아님** — 관심 있는 학생만 🔴 이상으로 자율 탐색.  
- React 맛보기·모던 프레임워크 지도가 필요하면 [appendix/modern-frameworks-guide.md](../appendix/modern-frameworks-guide.md) 참고 (정규 진도 아님, 선택 참고 자료).  
- `node_modules` 커밋 사고가 가장 흔하다 — `.gitignore`를 **`git add .` 전에** 만들도록 반복 강조.  
- Node.js/npm이 없는 학생은 Live Server 대안으로 소외 없이 진행.

### 설명용 한 장 요약 (칠판)


### FAQ

**Q. Node.js가 설치 안 돼 있어요.**  
A. 3주차 환경 세팅 자료로 설치하거나, 오늘은 Live Server 방식으로 진행 후 다음 시간에 보충.

**Q. React로 해도 되나요?**  
A. 이미 JS가 탄탄한 학생만. 학급 표준(Vite vanilla)에서 크게 벗어나면 도움을 늦게 받을 수 있음을 안내.

**Q. node_modules를 실수로 커밋했어요.**  
A. `.gitignore`에 추가 후 `git rm -r --cached node_modules` 후 재커밋 — 조교 호출 권장.

**Q. 이 Kit에 바로 미니앱 콘텐츠를 넣어도 되나요?**  
A. 가능하지만 오늘 목표는 **뼈대**. 콘텐츠는 9~10주차 미니앱 단계에서.
