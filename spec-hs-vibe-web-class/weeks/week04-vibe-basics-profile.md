> 탐구·포트폴리오에서 중요한 것은 「한 번에 예쁜 결과」가 아니라  
> **구조를 먼저 정하고 → 실행하고 → 고친 과정**이다.  
> 오늘 Plan 모드가 바로 그 근육이다.

## 1. Plan 모드란? — 「구조 먼저, 코드 나중」

### 1.1. 왜 필요한가?

| 바로 수정 모드만 쓸 때 | Plan을 쓸 때 |
|------------------------|--------------|
| AI가 마음대로 파일·섹션을 늘림 | 먼저 **설계안**을 보고 합의 |
| 「예쁘게」만 반복 → 구조가 흔들림 | 범위(Non-goals)를 먼저 자름 |
| 나중에 「이게 왜 여기 있지?」 | 「왜 이 구조인가」설명 가능 |

특목고 탐구와 동일:
**가설/계획 → 실행 → 수정** 순서.

### 1.2. Plan 모드에서 일어나는 일 (개념)

1. 네가 **큰 목표**를 말한다 (예: 프로필 웹 초안)  
2. AI가 **할 일 목록·파일 구조·섹션**을 제안한다  
3. 네가 **승인 / 수정 / 거절**한다  
4. 그다음에야 코드 작성으로 넘어간다  

> 도구 UI 이름은 Cursor Plan / Claude Code plan 등으로 다를 수 있다.  
> 수업에서는 기능을 **「계획 먼저 보기」** 로 부른다.

### 1.3. 언제 Plan? 언제 바로 수정?

| Plan (오늘 필수 연습) | 바로 수정 OK |
|----------------------|--------------|
| 새 페이지·섹션 추가 | 오타·문장 한 줄 |
| 레이아웃 전체 변경 | 색 하나, 글자 크기 |
| 파일 여러 개 생성 | 주석·제목만 변경 |
| 「처음부터 다시」 | 버그 한 줄 |

**규칙 (칠판):**  
> 파일이 2개 이상이 생기거나, 섹션이 늘어나면 → **Plan 먼저**.

### 1.4. 좋은 Plan 요청 예시

```
목표: 중학생 포트폴리오용 프로필 웹 초안을 만든다.

제약:
- HTML/CSS만 (React/Next 금지)
- 한 페이지 스크롤 + 섹션 id 앵커
- 한국어 UI
- 실명·학교·전화번호·얼굴 사진 넣지 말 것 (닉네임 OK)
- 오늘은 초안(v0). 배포·Git 언급하지 말 것

먼저 계획만 제안해줘:
1) 섹션 목록
2) 파일 구조
3) 각 섹션 최소 콘텐츠
4) 하지 않을 것 (Non-goals)

코드는 내가 "진행"이라고 한 뒤에만 작성해줘.
```

### 1.5. Plan을 검토하는 학생 체크리스트

- [ ] 섹션이 **5개 전후**인가? (너무 많으면 줄이기)  
- [ ] Projects가 **지금 비어 있어도** 자리가 있는가?  
- [ ] Contact에 민감정보가 강제되지 않는가?  
- [ ] 「하지 않을 것」이 적혀 있는가?  

**활동 (3분):** Plan 답변에서 Non-goals 한 줄을 빨간 펜(또는 하이라이트)으로 표시하기.

## 2. 권한(Permission)이란?

### 2.1. 한 줄 정의

AI 코딩 도구는 때로 **파일을 지우고, 명령을 실행하고, 많은 파일을 바꿀** 수 있다.  
**권한** = 「이 행동을 해도 될까?」를 너에게 묻는 안전장치.

### 2.2. 자주 보는 유형 (개념)

| 유형 | 예 | 학생 태도 |
|------|-----|-----------|
| 파일 읽기 | 프로젝트 분석 | 보통 허용 |
| 파일 쓰기/수정 | `index.html` 생성 | 목표가 맞으면 허용 |
| 파일 삭제 | 기존 파일 제거 | **한 번 더 읽기** |
| 터미널 명령 | 설치·실행 | 모르는 명령은 **교사에게** |
| 네트워크 | 패키지 다운로드 | Week4는 최소화 |

### 2.3. Accept / Deny / Plan과 연결

- **Accept:** 이 변경·명령 진행  
- **Deny / Reject:** 안 함 — 목표가 다르거나 위험해 보일 때  
- **Plan 경유:** 큰 변경은 계획 합의 후 Accept  

> 「무조건 Allow all」은 배우지 않는다.  
> 오늘은 **읽고 → 목표와 맞는지 → 허용** 습관.

### 2.4. 미니 시나리오 (교사와 함께)

1. AI: `index.html` 생성 제안 → 목표와 일치 → Accept  
2. AI: 기존 Week3 파일 삭제 제안 → 필요 없음 → Deny  
3. AI: 알 수 없는 `curl ... | sh` → Deny + 교사 호출  

### 2.5. 개인정보·안전

- Contact에 **진짜 전화번호·집주소** 넣지 않기  
- 학교 공식 이메일이 아니면 **플레이스홀더** (`hello@example.com` 금지 대신 `github.com/아이디` 자리만)  
- 얼굴 사진·친구 사진 무단 사용 금지

## 3. 프로젝트 초기화 (`/init`)와 분석

### 3.1. `/init`이 하는 일 (개념)

프로젝트를 AI가 일하기 좋은 상태로 **정리·요약**하는 절차다.  
도구에 따라:

- `/init` 슬래시 명령  
- 「이 폴더를 초기화하고 요약해줘」  
- `README` / 규칙 파일 초안 생성  

수업에서의 목적:
1. 빈 폴더에 **정체성**을 준다  
2. AI가 「이 프로젝트는 프로필 웹 초안」임을 기억하기 쉽게 한다  
3. (미리보기) 나중에 `CLAUDE.md`로 이어짐 — **본격은 5주차**

### 3.2. 함께 따라하기

1. Cursor에서 `week04-profile` 폴더 열기  
2. AI에게:

```
이 폴더는 중학생 포트폴리오용 프로필 웹 초안 프로젝트다.
한국어로 짧게:
1) 프로젝트 목적
2) 기술 범위 (HTML/CSS만)
3) 개인정보 규칙
을 README.md 초안으로 만들어줘.
코드(HTML)는 아직 만들지 마.
```

3. `README.md`가 생기면 읽기 — **틀린 가정은 고치기**

### 3.3. 프로젝트 분석 미션 (원본 M3 대응)

AI에게:

```
현재 폴더를 읽고, 있는 파일만 기준으로 상태를 요약해줘.
없는 기능을 있다고 말하지 마.
다음에 하면 좋은 작업 3가지만 제안해줘.
```

**성공:** 「빈 프로젝트 / README만 있음」처럼 **사실에 가까운** 요약.

## 4. 나 인터뷰하기 — AI에게 재료 주기

### 4.1. 왜 인터뷰인가?

AI는 너를 모른다.  
좋은 프로필은 **네 답변**에서 나온다.  
특목고 서류·면접도 「나에 대한 재료」가 있어야 한다.

### 4.2. 인터뷰 질문지 (학생 워크시트 · 10분)

아래를 노트에 채운다. **다 안 채워도 됨.** 빈칸은 「미정」.

```
1. 닉네임/이니셜:
2. 한 줄 소개 (20자 이내 느낌):
3. 요즘 관심사 3개:
4. 특목고/진로로 끌리는 이유 한 줄:
5. 해보고 싶은 프로젝트 아이디어 2개 (아직 없어도 OK):
6. Contact에 공개해도 되는 것: (GitHub 예정 / 없음 / 기타)
7. 절대 올리지 않을 것:
```

### 4.3. AI에게 넘기는 방법

```
아래는 내 인터뷰 답변이야. 이 내용만 사용해.
추측으로 학교명·실명·실존 이력을 만들어내지 마.

(여기에 답변 붙여넣기)

이 재료로 프로필 5섹션용 초안 카피(문구)만 먼저 제안해줘.
HTML은 아직.
```

**포인트:** 코드보다 **문구 합의**가 먼저면 Plan이 쉬워진다.

### 5.3. Plan으로 사이트맵 확정 (🟢 핵심)

3. 합의된 내용을 `notes/sitemap.md`에 저장  
4. **「진행해도 좋아」** 라고 명시하기 전까지 HTML 작성 금지에 가깝게 운영  

### 5.4. 「왜 이 구조인가」연습 (특목고형)

나쁜 예: 「AI가 이렇게 해서요.」  
좋은 예: 「먼저 나를 알게 하고, 관심사를 보여 준 뒤, 나중에 프로젝트 링크를 붙이려고요.」

## 6. 프로필 초안 만들기 (구현)

### 6.1. 구현 원칙

1. Plan·사이트맵 **승인 후** 코드  
2. HTML/CSS만  
3. 한 페이지 + `id="about"` 같은 앵커 (상단 메뉴는 🟡)  
4. 검증 = 브라우저 새로고침  

### 6.2. 생성 프롬프트 (승인 후)

```
합의된 sitemap대로 index.html (+ 필요 시 styles/main.css)을 작성해줘.

필수:
- 섹션 5개, 각 섹션에 id
- 한국어
- Projects는 "Coming soon" 카드 2개
- Contact는 플레이스홀더만 (가짜 개인정보 생성 금지)
- 반응형은 기본만 (완벽할 필요 없음)

비주얼:

### 6.3. 검증 체크리스트 (브라우저)

### 6.4. 손으로 한 군데 고치기 (필수 습관)

```

### 6.6. UI 톤 맞추기 (🟡)

학생에게 **형용사 2개**만 고르게 한다.  
예: `차분한 + 또렷한` / `밝은 + 간단한`

```
비주얼 톤: (형용사 2개)
색은 2~3개만. 섹션 구분은 여백과 제목으로.
sitemap 구조는 유지하고 CSS/스타일만 조정.
```

### 6.7. 모바일 한 곳 수정 (🟡)

1. 브라우저 창을 좁히거나 폰으로 열기  
2. 깨진 곳 1개 찾기 (글자 넘침, 가로 스크롤 등)  
3. AI에게 **증상만** 구체적으로:

```
창 너비 약 400px에서 Hero 제목이 화면 밖으로 넘쳐.
구조는 유지하고 그 문제만 고쳐줘.
```

### 6.8. Extended Thinking / 신중 모드 맛보기 (🔴)

큰 UI 개선 1회만:

```
프로필 초안의 가독성과 섹션 위계를 개선하고 싶어.
먼저 문제점 3개와 수정 계획을 제안하고,
내가 OK 하면 적용해줘.
과한 라이브러리·애니메이션 추가 금지.
```

> 도구에 `ultrathink` / Extended Thinking / 고노력 모드 등이 있으면 **맛보기**.  
> 없어도 「계획 먼저」프롬프트로 동일하게 연습 가능.

### 6.9. 다크/라이트 (🔴)

```
라이트 기본 + 다크 톤 대안을 CSS로 준비하거나,
단순 다크 배경 버전 중 하나만 적용해줘.
토글 버튼은 선택이지만, 깨지면 토글 없이 다크 고정 OK.
```
