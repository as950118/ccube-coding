## 1. Vibe Coding이란?

### 1.1. 한 줄 정의

**바이브코딩(Vibe Coding)** 이란,  
사람이 **의도(목표·느낌·제약)** 를 말하고, AI가 **코드를 제안·작성**하며,  
사람이 **검증·수정·결정**하는 방식으로 소프트웨어를 만드는 방법이다.

> ❌ 「아무 생각 없이 AI한테 맡기기」  
> ✅ 「내가 방향을 잡고, AI를 빠른 손발로 쓰기」

### 1.2. 왜 지금 배우는가?

| 예전 | 지금 |
|------|------|
| 문법부터 수개월 | AI가 초안을 빠르게 작성 |
| 「못 만듦」이 벽 | 「무엇을 만들지」가 벽 |
| 결과물 = 코드 실력 | 결과물 = **문제 정의 + 검증 + 설명** |

특목고 탐구·면접에서도 「어떻게 생각했는가」가 중요하다.  
바이브코딩은 그 **사고 과정**을 연습하기 좋은 도구다.

### 1.3. 오늘 쓸 4단계 루프 (외우기)

```
① 목표     무엇을 만들고 싶은가? (한 문장)
② 계획     어떤 파일/화면이 필요한가?
③ 실행     AI에게 구체적으로 시키기
④ 검증     브라우저로 확인하고, 이상하면 다시 ①
```

**활동 (2분):** 옆 친구에게 「오늘 내 목표 한 문장」 말하기.

예시  
> 「브라우저에서 열리는 자기소개 페이지를 만들고, 내 이름이 크게 보이게 한다.»

### 1.4. 나쁜 지시 vs 좋은 지시

| 나쁜 예 | 좋은 예 |
|---------|---------|
| 웹사이트 만들어줘 | 단일 `index.html`로 자기소개 페이지. 제목·한 줄 소개·관심사 목록. 한국어. 화려한 애니메이션 없이 읽기 쉽게. |
| 예쁘게 해줘 | 배경은 연한 회색, 제목은 크게, 본문은 읽기 쉬운 크기. 모바일에서도 글자가 잘리면 안 됨. |
| 알아서 해줘 | 파일은 `index.html` 하나만. CSS는 파일 안에 `<style>`로 넣어도 됨. |

## 1.1. LLM이란? (Large Language Model)

### 개념

**LLM(대규모 언어 모델)** 은 엄청난 양의 글을 학습해,  
다음에 올 **말·코드**를 예측하는 AI다.

비유:
- LLM = **아주 많이 읽은 조교**
- 질문(프롬프트) = 과제 지시서
- 답변 = 조교가 써 준 초안

### 학생이 알아야 할 3가지 진실

1. **틀릴 수 있다** — 자신 있게 틀린 코드를 낼 수 있다 → 그래서 **검증**이 필수  
2. **맥락을 잊을 수 있다** — 긴 대화면 앞부분을 놓친다 → 목표는 짧게 반복  
3. **비밀을 지키지 않는다** — 비밀번호·API 키를 채팅에 넣지 말 것  

### LLM이 잘하는 것 / 못하는 것

| 잘함 | 약함 |
|------|------|
| HTML/CSS 초안 | 「내 컴퓨터에 파일이 있는지」 혼자 모름 (도구 없이는) |
| 설명·번역·요약 | 최신 시험 범위·학교 내부 정보 |
| 반복 수정 | 네가 **무엇을 원하는지** 자동으로 알아채기 |

## 2. AI 툴 — 모델과 도구는 다르다

### 2.0. 핵심 구분 (칠판에 그리기)

```
[ LLM / 모델 ]          ← 뇌 (Claude, GPT, Gemini …)
       ↑
[ AI 코딩 도구 ]        ← 작업실 (Cursor, Claude Code …)
       ↑
[ 너 + 프로젝트 폴더 ]  ← 실제 파일
```

| | AI 모델 (채팅) | AI 코딩 도구 |
|--|----------------|--------------|
| 예 | ChatGPT 웹, Claude.ai | **Cursor**, **Claude Code** |
| 하는 일 | 대화로 답변 | 프로젝트 파일을 **읽고·고치고·실행 도움** |
| 결과 | 복사해서 붙여넣기 | 폴더 안에 파일이 **직접** 생김 |
| 비유 | 상담 | 같이 책상에 앉아 코딩하는 파트너 |

> 질문: 「꼭 Cursor를 써야 하나요?」  
> 답: 이 수업의 **표준 도구는 Cursor**다. 다른 도구도 가능하지만, 자료·데모는 Cursor 기준이다.

---

### 2.1. Claude Code란?

**Claude Code**는 Anthropic의 AI(Claude)를 **코딩 작업에 특화**해 쓰는 도구다.  
터미널(검은 화면)이나 IDE와 연결되어, 프로젝트 폴더를 기준으로:

- 파일을 읽고
- 코드를 수정하고
- 명령 실행을 제안한다

**오늘 수준에서 기억할 것**
- 「채팅만 하는 Claude」와 「폴더를 만지는 Claude Code」는 사용감이 다르다
- 권한(permission) 개념이 있다 → **2주차에 자세히** (오늘은 「허용/거부」만 느껴보기)

### 2.2. Cursor란?

**Cursor**는 VS Code와 비슷한 **코드 편집기(IDE)** 에 AI가 깊게 들어간 제품이다.

할 수 있는 것(오늘 쓰는 것):
- 폴더를 연다
- 파일을 보고 고친다
- AI 채팅/에이전트에게 「이 폴더 기준으로」 작업을 시킨다
- 터미널을 편집기 안에서 연다

**왜 수업 표준인가?**
- 화면이 한곳에 모여 있음 (파일 + AI + 터미널)
- 중학생이 「어디에 코드를 붙여넣지?」로 헤매는 시간을 줄임

### 2.3. 오늘 수업에서의 역할 분담

| 역할 | 담당 |
|------|------|
| 생각·목표·검증 | **학생** |
| 코드 초안·반복 수정 | **Cursor AI / Claude Code** |
| 코칭·막힘 구조화 | **교사** |

## 5. 터미널 익숙해지기

### 5.1. 터미널이란?

**터미널** = 글자로 컴퓨터에게 명령을 내리는 창.  
마우스 대신 **정확한 지시**를 줄 때 쓴다.  
Git, 실행, 설치가 모두 여기서 이뤄지는 경우가 많다.

비유: 파일 탐색기가 「손으로 집기」라면, 터미널은 「주소를 말하고 찾아가기」.

### 5.2. 오늘 배울 명령 3개 (+1)

| 명령 | 의미 | 기억 문장 |
|------|------|-----------|
| `pwd` | Print Working Directory — 지금 어디? | 「내가 서 있는 주소」 |
| `ls` | List — 뭐가 있지? | Mac/Linux. Windows는 `dir`도 OK |
| `cd 폴더이름` | Change Directory — 이동 | `cd ..` 는 한 단계 위 |
| `clear` | 화면 지우기 | 필수 아님, 있으면 편함 |

### 5.3. Mac vs Windows (왜 명령이 다르기도 할까?)

운영체제(OS)가 다르면 「기본 언어」가 다르다.  
수업에서는:

- Mac/Linux 스타일 (`ls`, `pwd`)을 **기준으로 설명**
- Windows PowerShell에서도 대부분 `ls`, `pwd`, `cd`가 동작하는 경우가 많음
- 안 되면 교사 치트시트 확인

### 5.4. 실습 (🟢)

터미널에서 순서대로:

```bash
pwd
ls
cd ccube-week01
pwd
ls
```

**성공:** 두 번째 `pwd`에 `ccube-week01` 경로가 보인다.

### 5.5. 자주 하는 실수

| 실수 | 해결 |
|------|------|
| 한글 폴더명·띄어쓰기 | 영문·하이픈 (`week01-intro`) |
| 잘못된 위치에서 `ls` | `pwd`로 위치 확인 후 `cd` |
| 대소문자 | Mac은 대체로 무시, 그래도 **정확히** |

## 6. 자기소개 페이지 만들어보기

### 6.1. 웹페이지가 뭐지? (최소 지식)

브라우저가 읽는 기본 문서는 **HTML**이다.

초간단 구조:

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <title>내 이름</title>
</head>
<body>
  <h1>내 이름</h1>
  <p>한 줄 소개</p>
</body>
</html>
```

| 태그 | 역할 |
|------|------|
| `<h1>` | 가장 큰 제목 |
| `<p>` | 문단 |
| `<ul>` `<li>` | 목록 |

오늘은 문법을 외우지 않는다. **AI가 만든 것을 읽고, 이름만 고친다.**

### 6.2. 함께 만들기 (교사 라이브 데모 → 학생 따라하기)

#### Step A — 목표 확정
학생 개인 목표 예:
> 「닉네임 ○○의 관심사(과학/언어/코딩)가 보이는 한 페이지」

#### Step B — AI에게 생성 요청
위의 프롬프트 템플릿에 **자기 이름·관심사**를 채워 보낸다.

#### Step C — 파일 확인
- 사이드바에 `index.html`이 생겼는지
- 내용에 이상한 영어 설명만 잔뜩인지 → 「HTML만 남겨줘」 재요청

#### Step D — 브라우저로 열기
방법 중 하나:
1. Finder/탐색기에서 `index.html` 더블클릭  
2. 브라우저로 드래그앤드롭  
3. Cursor에서 경로를 복사해 브라우저 주소로 (환경에 따라)

#### Step E — 검증 질문
- [ ] 이름이 보이는가?  
- [ ] 깨진 글자(�)가 없는가? → UTF-8/`lang="ko"` 요청  
- [ ] 내가 시킨 관심사가 맞는가?  

### 6.3. 직접 살짝 고치기 (이해 확인)

AI에게만 맡기지 말고, **한 군데는 손으로**:

1. `<h1>` 안의 글자 바꾸기  
2. 저장 (`Cmd/Ctrl+S`)  
3. 브라우저 **새로고침**  

→ 「내가 파일을 바꾸면 화면이 바뀐다」감각 = 오늘 핵심.
