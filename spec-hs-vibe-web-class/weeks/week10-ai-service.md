### 특목고 연결 (오늘 심을 한 문장)

> AI는 「똑똑한 검색창」이 아니라 **우리가 만든 서비스의 부품**이다. 부품으로 쓰려면 ① 키를 숨기고 ② 규칙을 고정하고 ③ 사실은 공공데이터에서 가져오고 ④ 틀릴 수 있음을 화면에서 구분해 알려야 한다 — 탐구·연구 활동에서 「AI가 준 답을 어떻게 검증했는가」를 설명하는 근거가 된다.

# 본문 — 챕터별 상세

## 0. 교사 사전 준비 (수업 전)

- [ ] **OpenAI API 키 준비.** API는 ChatGPT 구독과 별개의 **선불 크레딧 과금**이다. 학생 개인 결제는 받지 않고, 교사가 프로젝트를 만들어 키를 발급한다. 방식은 ① 학생별 키(권장, 프로젝트 예산 상한 설정) ② 수업 공용 키 — 어느 쪽이든 **공개 채널·GitHub에 키를 올리지 않는다**, 수업 종료 후 키를 폐기한다.
- [ ] **사용 한도(월 예산) 설정**. 무한 루프 호출로 과금되지 않도록 한다. 기본 모델은 저렴한 소형 모델(`gpt-4.1-mini`)이며, 수업용 사용량은 소액이다.
- [ ] **모델 이름 확인.** 코드의 기본 모델은 `gpt-4.1-mini`(텍스트+이미지 입력 지원). 계정에서 쓸 수 없으면 환경 변수 `OPENAI_MODEL`로 교체한다 — 이미지 입력을 지원하는 모델이어야 4장이 된다.
- [ ] **실제 키로 시연 1회** — [reference/week10-complete](../starters/reference/week10-complete/)를 돌려 본다. (완성 예시는 2026-09-20에 `gpt-4.1-mini`로 챗봇·공지 요약·선명한 사진 판독·급식 브리핑을 실제 호출로 확인함. 흐린 사진의 「확인 필요」 동작은 미확인 — 실물 사진으로 확인.)
- [ ] 시연용 사진 2장 준비: 글자가 선명한 시간표 1장, 일부러 흐리게/일부 가린 안내문 1장(「확인 필요」 표시 확인용). `notice.jpg`로 저장.
- [ ] 나이스 인증키는 선택이다. 키 없이도 샘플 모드(조회 5건 제한)로 학교 검색·급식 조회가 된다. 키를 발급받았다면 **학생에게 환경 변수로만 전달**한다.

## 1. 오늘 배우는 개념 압축 강의 (10분)

### 1.1. AI 서비스의 요청/응답 사이클

지금까지의 「브라우저 ↔ Flask ↔ DB」에 **외부 LLM API**가 하나 더 붙는다.

```
① 브라우저가 공지 텍스트·질문을 서버로 보낸다
② Flask(app.py)가 OPENAI_API_KEY를 붙여 OpenAI API에 전달한다      ← 키는 서버에만 있다
③ OpenAI 모델이 프롬프트 규칙에 따라 텍스트 응답을 생성한다
④ Flask가 결과를 템플릿에 담아 브라우저에 렌더링한다
```

### 1.2. 오늘 배우는 4개 키워드

| 키워드 | 한 줄 |
|--------|------|
| **openai SDK** | OpenAI 모델 호출을 표준화한 공식 Python 라이브러리 (`client.responses.create`) |
| **단일 대화 vs 연속 대화** | 문맥 없이 단발 호출(Stateless) vs **대화 기록을 직접 쌓아 매번 함께 보내기** |
| **System Instruction (`instructions`)** | 모델의 역할·응답 규칙·환각 방지 제약을 고정하는 최상위 지침 |
| **Grounding** | AI의 기억(추측)에 의존하지 않고, 공공데이터를 먼저 조회해 근거로 제공하는 기법 |

> **교사 포인트:** Gemini의 `chats.create`처럼 SDK가 대화 세션을 관리해 주는 방식과 달리, OpenAI 쪽은 **기록 리스트를 우리가 직접 관리**한다. 「AI가 기억한다」는 착각을 깨고 「연속 대화 = 이전 대화를 매번 같이 보낸 것」임을 코드로 보여줄 좋은 기회다. 이때 대화가 길어지면 토큰(비용)이 늘어나므로 기록 길이를 제한한다(`MAX_HISTORY`).

### 1.3. 오늘 하지 않는 것 (Non-goals)

- 스트리밍 응답(글자가 실시간으로 나오는 효과), 함수 호출(tool use)
- 사용자 로그인·DB에 챗봇 기록 저장 (서버 재시작 시 기록 사라짐을 한계로 인정)
- 배포 — 로컬(포트 5001)에서만 실행
- 학교 여러 곳 중 선택 UI — 같은 이름이면 첫 결과

## 2. 단일 대화와 연속 대화 (🟢)

### 2.1. 환경 준비

```
python -m pip install -U openai
```

`OPENAI_API_KEY`를 환경 변수로 등록한다 (PyCharm: Run → Edit Configurations → Environment variables, 또는 `.env` 파일 + python-dotenv). **코드에 키를 적지 않는다.**

### 2.2. 단일 대화 — `step1_single.py`

```python
from openai import OpenAI

client = OpenAI()   # 환경 변수 OPENAI_API_KEY를 자동으로 읽는다
MODEL = "gpt-4.1-mini"

response = client.responses.create(
    model=MODEL,
    input="학교생활을 돕는 반장봇의 핵심 기능 3가지를 bullet point로 추천해 줘.",
)
print(response.output_text)
```

### 2.3. 연속 대화 — `step2_chat.py`

핵심은 `history` 리스트에 **질문과 답변을 모두 쌓아 매번 통째로** 보내는 것이다.

```python
history = []
...
history.append({"role": "user", "content": question})
response = client.responses.create(model=MODEL, input=history)
answer = response.output_text
history.append({"role": "assistant", "content": answer})
```

### 2.4. 검증 체크리스트

- [ ] `step1`을 두 번 연속 실행했을 때 두 번째가 첫 번째를 기억하지 못한다
- [ ] `step2`에서 「내일 체육 준비물은 물이야」 → 「내일 뭘 챙겨야 해?」에 「물」이라고 답한다
- [ ] 「초기화」 입력 후 다시 물으면 이전 준비물을 잊는다
- [ ] (질문) `history`를 출력해 보면 무엇이 들어 있는가? → 매번 다 함께 보내는 것을 눈으로 확인

## 4. 멀티모달 — 사진 분석 (🟡)

이미지를 **base64 문자열**로 바꿔 `data:` URL로 텍스트 프롬프트와 **같은 메시지**에 담는다 (`step4_image.py`).

```python
{"type": "input_text",  "text": prompt},
{"type": "input_image", "image_url": f"data:{MIME_TYPE};base64,{image_b64}"},
```

### 검증 체크리스트

- [ ] JPG → `image/jpeg`, PNG → `image/png`로 MIME 타입을 맞췄다
- [ ] 사진의 글자와 AI 출력을 **글자 단위로** 대조했다(누락·오독 표시)
- [ ] 일부러 흐린 사진에서 「확인 필요」가 표시되는지 확인했다

> **교사 포인트:** 「AI가 읽은 것」은 검증 대상이다. 오독이 나오면 실패가 아니라 **좋은 관찰 자료**다 — `notes/ai-log.md`에 적게 한다.

## 5. Flask + 나이스 급식 결합 (🔴)

### 5.1. 구성

| 파일 | 역할 |
|------|------|
| `neis.py` | 학교 이름 → 학교 코드, 학교 코드 → 오늘 급식 원문(중식 우선). 키 없이 샘플 모드로 동작 |
| `app.py` | `/`(급식·공지·사진, 결과를 화면에 렌더링), `/chat`(챗봇 JSON API), 브라우저별 대화 기록 `user_chats[session["user_key"]]` |
| `templates/index.html` | 급식 원문(초록)과 AI 해설(보라)을 **시각적으로 분리**, 챗봇은 `fetch("/chat")` |

코드는 [완성 예시](../starters/reference/week10-complete/)와 학생 자료(docs/10주차)의 5장에 있다.

### 5.2. Grounding 설명 포인트

챗봇은 공지 요약과 **다른 시스템 지침**(`CHAT_PROMPT`)을 쓴다 — 공지용 지침을 그대로 쓰면 학생이 대화로 알려준 준비물을 「공지에 없다」며 무시하기 때문이다(실제로 겪은 문제). 시스템 지침이 동작을 좌우함을 보여줄 수 있다.

`app.py`의 `brief_meal()` — **원문을 프롬프트에 먼저 넣고**, 「원문에 없는 것은 지어내지 마」와 함께 **알레르기 번호표**까지 근거로 제공한다. 번호표를 주지 않으면 모델이 번호의 뜻(예: 5=대두)을 기억에 의존해 틀릴 수 있다.

### 5.3. 「AI 응답을 화면에 그냥 붙여도 될까?」 (보안 한 컷)

챗 응답을 `innerHTML`에 그대로 넣으면 응답에 섞인 HTML/스크립트가 실행될 수 있다. 완성 예시는 `textContent` 계열만 써서 막았다 — 「외부에서 온 글은 코드가 아니라 글로 다룬다」를 한 문장으로 짚는다.

### 5.4. 검증 체크리스트

- [ ] 학교 이름 조회 시 나이스 원문 급식이 정상 출력된다
- [ ] AI 브리핑이 원문에 기반해 별도 영역에 나온다
- [ ] 브라우저 두 개(시크릿 창 포함)에서 대화가 섞이지 않는다

## 트러블슈팅

| 증상 | 원인 및 해결 |
|------|--------------|
| `ModuleNotFoundError: No module named 'openai'` | 실행 인터프리터에 패키지 없음. `python -m pip install -U openai` |
| `OpenAIError: Missing credentials ...` (api_key 관련) | `OPENAI_API_KEY` 미설정. PyCharm 실행 설정의 Environment variables 확인 (설정 후 앱 재시작) |
| `AuthenticationError` / 401 | 키 오타·폐기·만료. 새 키로 교체 |
| `RateLimitError` / 429 | 분당 호출 한도 또는 크레딧·예산 소진. 루프 내 반복 호출 금지, 잠시 대기 / 교사에게 예산 확인 |
| `model_not_found` / 404 | 계정에서 쓸 수 없는 모델. `OPENAI_MODEL` 환경 변수로 교체 (이미지 입력 지원 모델이어야 함) |
| 이미지 분석 시 400 오류 | 지원하지 않는 형식(GIF·HEIC 등) 또는 MIME 불일치. JPG/PNG만 사용 |
| 다른 브라우저의 대화가 섞임 | 전역 변수 하나로 대화 기록 공유. `session['user_key']` 기반 딕셔너리로 분리 |
| 급식이 안 나옴 | 주말·방학·휴업일이거나 학교 이름 오타. 실제 급식이 있는 평일에 재시도 |
| 서버를 껐다 켜니 대화가 사라짐 | 정상 — 기록을 메모리에 두었기 때문. 파일/DB 저장은 오늘의 범위 밖 |
