# 왜 3단으로 나눴는가 (예시)

화면(템플릿)과 데이터 저장(DB)을 같은 파일에 뒤섞으면, 화면만 고치고 싶을 때도 저장 로직까지 다 읽어야 한다. 역할을 나눠 두면 "화면이 이상하면 templates/, 저장이 안 되면 app.py의 쿼리"처럼 문제 위치를 빠르게 좁힐 수 있다.

# 오늘 막혔던 점 (예시)

- `INSERT` 후 `conn.commit()`을 빼먹어서 글이 저장 안 된 것처럼 보였음 → commit 추가로 해결
- 상세 페이지 라우트에 `<int:post_id>`가 아니라 `<post_id>`로 적어서 문자열 비교가 안 맞았음 → `int:` 추가로 해결
