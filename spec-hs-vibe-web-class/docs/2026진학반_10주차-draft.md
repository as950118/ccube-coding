## 오늘 배우는 것

**미니앱 MVP 구현 · 배포 (포트폴리오 #2)**

오늘은 미니앱 주제를 그 자리에서 정하고, 핵심 기능만 빠르게 만들어 **실제로 인터넷에 배포**합니다.
저장이 꼭 필요한 주제(글쓰기·방명록·좋아요 등)라면, 화면(프론트)·서버(백엔드)·저장소(DB)를
서로 다른 서비스로 나누는 **3단 구조**까지 도전할 수 있습니다.

## 오늘 만드는 것

| 트랙 | 난이도 | 내용 |
|------|--------|------|
| 미니앱 (프론트만) | 🟢 | 화면만 있는 미니앱을 Vercel/GitHub Pages에 배포 |
| 3단 구조 (선택) | 🔴 | 저장이 필요하면 Vercel(화면) + Render(서버) + Supabase(DB)로 나눠 배포 |

## 핵심 개념

- **MVP**: 완벽한 앱이 아니라, 문제를 해결하는 **최소 기능**부터 먼저 완성하고 배포하는 것
- **3단 아키텍처**: 프레젠테이션(화면) · 애플리케이션(로직) · 데이터(저장)를 서로 다른 역할로 나누는 방식
- **왜 나누나**: DB에 접근하는 비밀 키를 화면(프론트) 코드에 그대로 두면 누구나 볼 수 있음 → 서버(백엔드)만 그 키를 갖고, 화면은 서버에만 요청하도록 나눔

```
🟢 기본:  화면(Vercel) → 그걸로 끝, 저장 없음
🔴 선택:  화면(Vercel) → 서버(Render) → 저장소(Supabase)
          비밀 키는 서버에만 있고, 화면은 서버 주소만 안다
```

## 오늘의 순서

1. 미니앱 주제 정하기 · 미니 PRD(문제 · 핵심 기능 3개 · 하지 않을 것) — 저장이 필요한 주제인지 이때 판단
2. 골격 생성 (라우팅/페이지 구조) — 🔴는 Supabase 프로젝트·테이블도 함께 준비
3. 핵심 기능 1~2개 구현 — 🔴는 서버(API) 코드도 함께 작성
4. 배포 (Vercel 또는 GitHub Pages) — 🔴는 서버를 Render에 먼저 배포한 뒤 화면에 서버 주소를 연결
5. README에 문제·데모·사용법 정리, 프로필 웹 Projects에 카드 추가
6. 1분 시연 · 회고 3줄
