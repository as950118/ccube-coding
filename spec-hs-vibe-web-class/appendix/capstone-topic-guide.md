# 캡스톤 주제 선정 가이드

> [weeks/week11-capstone-ideation.md](../weeks/week11-capstone-ideation.md)의 「특목고형 주제 가이드」를 확장한 문서.
> Week11 수업 준비용이자, 학생에게 그대로 나눠줘도 되는 워크시트.

---

## 1. 이 문서가 필요한 이유

캡스톤(포트폴리오 #3)은 [03-assessment.md](../03-assessment.md) Rubric에서
**「문제정의」** 항목의 최고 등급(⭐⭐⭐)이 **「특목고 관심사와 연결 설명」**일 만큼
주제 자체가 평가의 핵심이다.

주제가 좋으면:
- PRD·ROADMAP이 저절로 써진다 (누구의 무슨 문제인지 명확하므로)
- 발표 스크립트 1번 "저는 ○○ 문제를 풀고 싶었습니다"가 바로 나온다
- 2주 MVP 범위가 자연스럽게 좁혀진다

주제가 막연하면 12~13주차 내내 범위가 흔들린다. **11주차에 시간을 써야 하는 이유.**

## 2. 주제 선정 사고 과정 (5단계)

학생이 순서대로 채우면 주제가 나오도록 설계. Week11 블록 B~C에서 1:1 코칭 시 이 순서로 질문한다.

| 단계 | 질문 | 산출물 |
|------|------|--------|
| ① 관심사 나열 | 나는 교과·동아리·취미·일상에서 뭘 좋아하나? (3~5개) | 관심사 리스트 |
| ② 불편 포착 | 그 관심사 안에서 **누가, 어떤 순간에, 뭐가 불편한가**? | "OO는 XX할 때 불편하다" 한 문장 |
| ③ 계열 연결 | 이 불편이 내가 가고 싶은 특목고(과학고/외고/국제고 등) 공부와 어떻게 이어지나? | 연결 스토리 1줄 |
| ④ 실현성 체크 | 2주 안에 화면 하나로 보여줄 수 있나? 데이터·API는 구할 수 있나? | Go / No-go |
| ⑤ 한 문장 피치 | 위 내용을 압축 | "나는 [누구]의 [어떤 불편]을 [무엇]으로 돕는다" |

### 핵심 원칙
- **①→②가 제일 중요.** 관심사(예: "우주")에서 멈추면 주제가 아니라 카테고리다. 반드시 "불편"까지 내려가야 한다.
- ③은 억지로 끼워맞추지 않는다. 못 끼워맞추면 ①로 돌아간다.
- ④에서 막히면 주제를 좁힌다 (기능을 빼는 것이지, 완전히 새 주제를 찾는 게 아니다).
- **①②가 막막한 학생은** 바로 아래 [3. 학생용 몸풀기 질문지]부터 시작시킨다.

## 3. 학생용 몸풀기 질문지 (아이디어 브레인스토밍)

바로 "네 프로젝트 주제가 뭐야?"라고 물으면 대부분 막힌다.
아래 질문에 **떠오르는 대로, 완성도 신경 쓰지 말고** 최대한 많이 적게 한다.
Week11 블록 B(0:25~1:25) 초반 15분, 개인 작업으로 진행.

### 사용법
1. A~E 카테고리 질문에 최대한 많이 답 적기 (15분, 단어만 나열해도 OK)
2. 적은 것 중 눈길이 가는 3개에 별표(★)
3. 가장 마음이 가는 1개를 골라 → [2. 주제 선정 사고 과정] ①②단계로 이동

### A. 반복되는 일 찾기
- 나는 아침에 일어나서 학교 가기 전까지 어떤 일을 매일 반복하나?
- 학교에서 매주 똑같이 되풀이되는 일과는?
- 가족 중 누군가 매일·매주 반복해서 하는 일은? (지켜본 적 있는 것)
- 내가 속한 동아리·모임에서 매번 똑같이 하는 절차는?
- "이거 또 해야 돼?"라고 생각했던 일은?

### B. 불편했던 경험 찾기
- 최근 일주일 안에 "아 짜증나"라고 느낀 순간은? 왜 그랬나?
- 뭔가를 찾느라 시간을 오래 썼던 경험은? (물건 · 정보 · 사람)
- 종이나 메모장에 손으로 적어서 관리 중인 게 있나? 뭐가 불편한가?
- 친구·가족이 "이거 왜 이렇게 불편하지"라고 말한 걸 들은 적 있나?
- "누가 미리 알려줬으면 좋았을 텐데"라고 생각한 순간은?

### C. "있으면 좋겠다" 상상해보기
- 마법처럼 뭐든 만들 수 있다면, 학교·동아리·일상에 뭘 만들고 싶나?
- 평소에 "이런 앱·사이트 있으면 좋겠다"라고 생각해본 적 있나?
- 내가 좋아하는 것(과목·취미·게임)을 더 편하게 즐기려면 뭐가 필요할까?
- 누군가를 도와주는 걸 만든다면, 누구를 돕고 싶나?

### D. 내가 잘 아는 분야에서 찾기
- 내가 남들보다 많이 알거나 관심 있는 분야는? (과목·취미·특기)
- 그 분야에서 초보자가 겪는 어려움은 뭘까?
- 그 분야 정보를 나는 지금 어디서 얻나? 그 방법이 불편하지는 않나?

### E. 주변 사람 관찰하기
- 최근 부모님·선생님·친구가 불평하거나 힘들어하는 걸 본 적 있나? 무엇 때문에?
- 나보다 어린 후배·신입생이 겪을 어려움은 뭘까?
- 우리 학교·동네에서 "이거 정리 좀 됐으면"하는 게 있나?

### 코칭 팁 (교사용)
- 학생이 "없는데요"라고 하면 카테고리를 바꿔본다 (A가 막히면 C로)
- 답이 단어 나열(예: "축구")에 그치면 "그거 하다가 짜증났던 적은?"으로 B를 다시 유도한다
- 별표 3개 중 고민되면 **"발표에서 90초 시연 장면이 그려지는 것"**을 우선시킨다

## 4. 계열별 주제 뱅크

교사가 코칭 중 막힌 학생에게 **방향 예시**로만 제시. 그대로 베끼게 하지 말고 학생 본인 경험으로 바꾸게 유도.

### 과학고 · 영재고 지망

| 예시 주제 | 누구의 어떤 불편 |
|-----------|------------------|
| 실험 기록 웹 | 조별 실험할 때 종이 기록이 흩어지고 그래프를 손으로 그려야 함 |
| 관찰 로그 (동식물·날씨·별자리) | 며칠에 걸친 관찰 데이터를 한눈에 비교하기 어려움 |
| 자연현상 시뮬레이터 (물리·화학 공식 시각화) | 교과서 공식이 그래프로 안 와닿음 |
| 우리 학교 에너지·환경 데이터 대시보드 | 급식 잔반량·분리수거량 등 학교 데이터가 눈에 안 보임 |
| 수학 문제 유형별 오답 분석기 | 내가 어떤 유형에서 반복해서 틀리는지 스스로 파악 안 됨 |

### 외고 · 국제고 지망

| 예시 주제 | 누구의 어떤 불편 |
|-----------|------------------|
| 뉴스 한 줄 비교 (같은 사건, 다른 나라 시각) | 한국 뉴스만 보면 국제 이슈를 한쪽 시각으로만 접함 |
| 언어 학습 미니 도구 (단어장·발음 체크리스트) | 시판 앱은 기능이 너무 많고 내 진도에 안 맞음 |
| 문화 비교 아카이브 (명절·음식·관용어) | 관심 국가 문화를 정리한 자료가 흩어져 있음 |
| 교내 다문화·교환학생 소개 웹 | 전학 온 외국인 학생 정보가 학생들에게 공유 안 됨 |
| 시사 이슈 찬반 정리 보드 | 토론 준비할 때 근거 자료를 매번 새로 찾아야 함 |

### 로봇마이스터고 지망

> 이 과정은 웹 코딩 수업이므로 로봇 하드웨어 자체를 만드는 게 아니라
> **로봇 활동(설계·제어·데이터·통신)을 돕는 웹 도구**로 방향을 잡는다.

| 학과 (지망) | 예시 주제 | 누구의 어떤 불편 |
|-------------|-----------|------------------|
| 로봇설계과 (로봇메이커) | 로봇 부품 재고·BOM 관리 웹 | 동아리에서 로봇 만들 때 부품 수량·버전이 파악 안 됨 |
| 로봇설계과 (로봇메이커) | 3D프린팅 출력 기록 로그 | 출력 실패 원인·설정값을 매번 기억에 의존함 |
| 로봇제어과 (제어 전문가) | 로봇 동작 시퀀스 체크리스트 | 대회 전 동작 순서를 종이로 확인해 실수가 잦음 |
| 로봇제어과 (제어 전문가) | 센서·모터 튜닝 결과 기록기 | 값 바꿀 때마다 이전 결과와 비교할 방법이 없음 |
| 로봇시스템과 (AI·빅데이터) | 로봇 주행 로그 시각화 대시보드 | 수집한 센서 데이터를 그래프로 못 보고 숫자로만 봄 |
| 로봇시스템과 (AI·빅데이터) | 대회 경기 기록 분석기 | 지난 대회 기록이 흩어져 있어 성장 비교가 안 됨 |
| 로봇정보통신과 (정보통신) | IoT 장비 상태 모니터링 웹 | 여러 장비 상태를 각각 확인해야 해서 번거로움 |
| 로봇정보통신과 (정보통신) | 통신 프로토콜 문서 위키 | 팀원마다 통신 규격을 다르게 알고 있어 혼선이 생김 |

### 공통 (학교 · 지역 · 또래)

| 예시 주제 | 누구의 어떤 불편 |
|-----------|------------------|
| 급식 메뉴 리뷰·별점 | 오늘 급식이 뭔지, 맛있었는지 후배들이 미리 알 수 없음 |
| 동아리 모집·활동 아카이브 | 동아리 정보가 대자보에만 있고 검색이 안 됨 |
| 통학길 정보 공유 (버스·도보 팁) | 신입생이 등하교 경로를 매번 물어봐야 함 |
| 스터디 매칭 게시판 | 같은 과목 스터디원을 구하기 어려움 |
| 지역 도서관·독서실 좌석 현황 | 자리 있는지 가봐야 아는 불편 |

> 이 표는 **출발점**이지 정답 목록이 아니다. 학생이 본인 경험에서 못 뽑으면 여기서 하나 골라
> "나라면 무엇을 다르게 하고 싶은가"로 변형시킨다.

## 5. 좋은 주제 체크리스트

Week11 원본 기준 그대로. 셋 다 Yes면 확정.

- [ ] **2주 안에 MVP 가능한가** (화면 1~2개, 핵심 기능 1개로 축소 가능)
- [ ] **"내가 왜 하는가"를 30초로 설명 가능한가** (본인 경험·관심에서 나옴)
- [ ] **데모가 한 화면에 보이는가** (발표 90초 시연에 들어감)

## 6. 피해야 할 주제와 이유

| 피할 것 | 이유 |
|---------|------|
| 거대 SNS·쇼핑몰 클론 | 2주에 안 끝남 → MVP 실패 → 발표에서 미완성만 보여줌 |
| 데이터·API 접근 불가 주제 (예: 실시간 공공데이터인데 인증 승인이 몇 주 걸림) | 구현 전에 조사 단계에서 막힘 |
| 개인정보 대량 수집형 (실명·연락처 DB화 등) | 중학생 프로젝트로 부적절 + 배포 시 문제 소지 |

막힌 학생을 만나면 "이 주제가 왜 안 되는지"보다 **"범위를 어디서 줄이면 되는지"**로 대화를 이끈다.
(예: "학교 전체 SNS" → "우리 반 공지 게시판"으로 축소)

## 8. 평가로 이어지는 지점

[03-assessment.md](../03-assessment.md) Rubric과의 연결:

| 이 문서의 단계 | Rubric 항목 | ⭐⭐⭐ 조건 |
|----------------|-------------|-------------|
| ②불편 포착 | 문제정의 | 「누구의 어떤 고통」이 명확 |
| ③계열 연결 | 문제정의 | 특목고 관심사와 연결 설명 |
| ④실현성 체크 | 실행 | MVP가 안정적으로 동작 |
| ⑤한 문장 피치 | 발표 | 왜/어떻게가 스크립트에 그대로 들어감 |

이 워크시트를 채운 학생은 14주차 발표 스크립트 1번 문장을 이미 갖고 있는 셈이다.
